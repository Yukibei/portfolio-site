# 个人站 V2 素材盘点与信息架构

> 文档性质：讨论稿，供视觉改造与素材入库前评审使用。  
> 更新时间：2026-08-03。  
> 当前状态：V2 多页面框架、首批真实素材和项目案例页已完成，本轮保持本地验证，暂不发布。

## 1. 本轮结论

个人站现在的问题不是“缺少特效”，而是内容规模已经超过原来的三项目单页结构。继续在现有长页里叠真人、跑马灯、恐龙、固定三图卡片，只会让身份、项目和工程证据互相争抢注意力。

V2 已保留 Next.js 15.4、React 19、Tailwind CSS v4 和现有视觉资产，并改造成可扩展的作品集系统：

- 首页负责建立身份、展示 4～6 个精选项目和当前在线服务。
- `/work` 收纳全部项目，`/work/[slug]` 承载视频、截图、架构、指标和技术决策。
- `/lab` 收纳动态组件、3D 工作证、TracePlayer 等实验性内容。
- `/notes` 承载个人博客与工程笔记。
- `/about` 承载真人肖像、经历、荣誉、简历和联系方式。
- `/services` 展示个人站、中转站、已部署入口与后续服务状态。

这样既保留网站的个人感，也不会让首页变成所有模块的堆叠页。

## 2. 当前三个直接问题

### 2.1 真人段不是图片本身差，而是使用方式失控

相关文件：

- `web/components/hero/PortraitHero.tsx`
- `web/components/hero/PortraitReveal.tsx`
- `web/public/hero/portrait-base.webp`
- `web/public/hero/portrait-crt.webp`
- `web/public/hero/side-human.webp`
- `web/public/hero/side-crt.webp`

当前段落占用约 `200vh`，同时出现正面真人、CRT 头、侧面真人、侧面 CRT、两行跑马灯、巨型姓名、签名、能力标签和恐龙。主体过多，真人更像特效素材，而不是可信、稳定的个人身份。

建议：

- 保留 `portrait-base.webp`，但优先用于 `/about` 的个人档案场景，不再承担长距离滚动特效。
- 首页只保留一个明确的人物画面，文字与人物形成稳定构图；不再同时叠四个人物图层。
- CRT 版本移动到 `/lab`，作为“人 / 系统”交互实验，不与个人介绍争抢主叙事。
- 新拍一张横向环境人像：本人在工作台、显示器或服务器环境中，主体偏一侧，给标题留出负空间。它比抠图证件式正面照更适合首页。
- 如需动态人物，优先录制真实 4～6 秒固定机位循环片段，不使用容易出现面部变形的生成视频。

### 2.2 恐龙保留，但离开姓名视觉主轴

人物终局中的恐龙不再只承担装饰状态，也不再放在右上角成为孤立标记。它现在位于签名与能力标签下方，作为明确但克制的可玩入口。

本轮已采用以下处理：

1. Loading Gate 中继续保留原有恐龙跑动动画，负责进入首页时的加载反馈。
2. 人物终局的签名下方显示可点击的小恐龙；点击后在人物段之后下拉展开紧凑游戏，不跳转到占满整页的独立页面。
3. 404 页面直接复用同一套真实 Canvas 游戏，支持键盘、点击、触摸、跳跃、下蹲、碰撞、计分与本地最高分。
4. `/lab/dino-runner` 仅兼容历史链接，并重定向到首页游戏锚点。

### 2.3 项目图片被固定模板绑死

相关文件：

- `web/components/Projects.tsx`
- `web/components/evidence/caseStudies.ts`

当前 `images: { a, b, tall }` 强制每个项目使用同一组三图布局，`object-contain` 又把横图放进固定深色窗口，容易形成大面积黑边。随着项目增加，逐张全屏 sticky 卡片也会让首页长度线性膨胀。

建议：

- 首页精选项目改为真实比例的编辑式媒体网格，不统一套 macOS 窗口壳。
- 横屏产品图、手机截图、竖向报告、视频和架构图分别采用合适比例。
- 项目详情页再展示完整证据链；首页只给一张主媒体、一个结果和一个关键取舍。
- `caseStudies.ts` 当前约 270 行，只有 3 个项目；继续追加会很快超过 300 行。V2 应按项目拆分数据文件，并把媒体类型升级为带用途和比例的结构。
- 首页项目区已采用 MotionSite「Features Chess」式交替图文结构、英文衬线斜体标题和液态玻璃表面，但全部替换为本人项目的真实媒体。

建议的新媒体字段：

```ts
type ProjectMedia = {
  kind: "image" | "video" | "diagram" | "trace";
  role: "cover" | "product" | "mobile" | "architecture" | "result";
  src: string;
  poster?: string;
  alt: string;
  caption: string;
  aspectRatio: `${number}/${number}`;
  fit: "cover" | "contain";
};
```

该媒体模型、真实比例拼贴和 `/work/[slug]` 案例模板已经落地；后续只需持续补充脱敏素材与演示视频。

## 3. 推荐信息架构

```text
/
├─ 首页：身份、精选项目、在线服务、最近文章、联系入口
├─ /work：全部项目索引与筛选
├─ /work/[slug]：单项目案例详情
├─ /lab：动态组件、3D、AI trace、交互实验
├─ /notes：博客与工程笔记
├─ /notes/[slug]：文章正文
├─ /services：个人站、中转站、项目入口与服务状态
└─ /about：肖像、经历、荣誉、简历、联系方式
```

主导航现为：`Work / Lab / Notes / Services / About / Resume`，为后续在线项目和新功能模块保留稳定扩展入口。

首页建议顺序：

1. Hero：姓名、方向、当前工作状态、查看项目与下载简历。
2. Selected Work：4～6 个精选项目，不把全部项目铺在首页。
3. Live Systems：已部署服务、运行状态、最近一次发布。
4. Recent Notes：3 篇近期文章。
5. About Strip：一张环境人像、一段简短介绍、联系方式。

## 8. 媒体规格与性能预算

### 图片

- 首页项目主图统一准备 1600×1000 或等价 8:5 比例，保留原始截图，另生成 AVIF/WebP。
- 手机截图保留 390×844 一类真实比例，用设备列或拼贴，不拉伸进横框。
- 架构图使用清晰 PNG/WebP；只有图标和纯矢量线稿才考虑 SVG。
- 每张图片必须有中文 `alt` 和说明，脱敏后再进入 `public`。

### 视频

- 首页自动循环片段建议 3～8 秒、静音、`playsInline`、带 poster，单段目标不超过 2 MB。
- 详情页演示建议 20～40 秒，单段目标 4～8 MB；更长内容按需加载或使用对象存储/CDN。
- 首屏之外的视频进入视口再加载，同时只允许一个视频主动播放。
- 所有视频保留静态 poster，并提供暂停控制与 reduced-motion 降级。
- 原始大视频不要直接放进 Git 仓库或 Next.js 构建产物。

### 全站预算

- 首屏初始媒体目标不超过 2.5 MB。
- 首页同时活动的重动效不超过一个；Three.js、视频与滚动特效不能同屏争抢 GPU。
- 项目媒体建议放对象存储/CDN，站点只维护 manifest、poster 和必要的小体积资产。
